# 🛡️ Linux 云服务器安全加固标准操作手册

> **适用系统**：Ubuntu / Debian（针对 CentOS/RHEL 部分命令有备注）
> **核心原则**：先建立新通道，再关闭旧通道；永远保留一个备用连接（如阿里云 VNC 控制台）以防锁死。

---

## 🚦 阶段一：云控制台网络层配置（阿里云/腾讯云等）
在登录服务器之前，先在网页控制台完成初步防护。

1. **安全组规则收紧**：
   * **SSH 端口 (22)**：建议将授权对象从 `0.0.0.0/0` 改为**你的固定公网 IP**（若 IP 不固定则保持默认）。
   * **Web 端口 (80/443)**：对 `0.0.0.0/0` 开放。
   * **其他高危端口**：绝对不要对公网开放（如 3306 数据库、6379 Redis 等）。
2. **配置自动快照策略**：
   * 路径：控制台 -> 存储与快照 -> 自动快照策略。
   * 建议：每天凌晨执行，保留 7 天，并**绑定到实例**。

## 👤 阶段二：账号与 SSH 权限体系加固
**登录方式**：使用 root 账号登录，或通过云控制台 VNC 进入。执行过程中**绝对不要关闭当前终端窗口**。

### 1. 创建普通用户并赋予 sudo 权限
```bash
# 1. 创建用户（将 codepencil 替换为你想要的名字）
adduser codepencil

# 2. 将用户加入 sudo 组（Ubuntu/Debian）
usermod -aG sudo codepencil
# 备注：如果是 CentOS/RHEL，请将 sudo 替换为 wheel

# 3. 验证提权是否成功
su - codepencil
sudo whoami  # 输入密码后应返回 root
```

### 2. 禁用 root 的 SSH 密码登录
切回 root 权限，修改 SSH 配置文件：
```bash
# 1. 备份配置文件（好习惯）
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak

# 2. 编辑配置文件
sudo nano /etc/ssh/sshd_config
```

在文件中找到 `PermitRootLogin` 这一行，修改为：
```ini
PermitRootLogin no
```
*保存退出（Ctrl+O -> Enter -> Ctrl+X）。*

```bash
# 3. 重启 SSH 服务生效（注意 Ubuntu 服务名为 ssh，CentOS 为 sshd）
sudo systemctl restart ssh
```

### 3. 生死验证（关键！）
**保持当前窗口不关**，新开一个终端：
*   **测 root**：`ssh root@服务器IP` （应报错 Permission denied，证明加固成功）。
*   **测普通用户**：`ssh codepencil@服务器IP` （应能正常登录，证明退路还在）。

## 🚫 阶段三：部署 fail2ban-rs 动态防御

> `fail2ban-rs` 是 Rust 重写的轻量替代品，常驻内存约 **1–10 MB**，适合小内存 VPS。配置为 TOML 格式，与 Python 版 `fail2ban` 的 `jail.local` **不兼容**。

### 1. 安装 fail2ban-rs

```bash
# 官方一键安装（需 root）
sudo bash -c "$(curl -sSfL https://raw.githubusercontent.com/aejimmi/fail2ban-rs/main/scripts/install.sh)"

# 若 GitHub 访问困难，可使用镜像前缀：
# sudo bash -c "$(curl -sSfL https://gh-proxy.com/https://raw.githubusercontent.com/aejimmi/fail2ban-rs/main/scripts/install.sh)"
```

安装完成后会生成：
- 二进制：`/usr/local/bin/fail2ban-rs`
- 配置：`/etc/fail2ban-rs/config.toml`
- 服务：`/etc/systemd/system/fail2ban-rs.service`

如果之前安装过 Python 版 fail2ban，先停用避免冲突：
```bash
sudo systemctl disable --now fail2ban 2>/dev/null || true
```

### 2. 确认日志文件与时间格式

```bash
# 确保 auth.log 存在
sudo test -f /var/log/auth.log || sudo touch /var/log/auth.log

# 查看时间戳格式（取第一行前 25 个字符）
sudo head -1 /var/log/auth.log | cut -c1-25
```

- 输出类似 `2026-11-02T12:49:03.840092` → 使用 `date_format = "iso8601"`
- 输出类似 `Nov  2 12:49:03` → 使用 `date_format = "syslog"`

> 若 `/var/log/auth.log` 为空且没有 SSH 日志，安装并启用 rsyslog：
> ```bash
> sudo apt install rsyslog -y
> sudo systemctl enable --now rsyslog
> ```

### 3. 写入 sshd 防护配置

```bash
sudo tee /etc/fail2ban-rs/config.toml > /dev/null <<'EOF'
[global]
ban_count_decay = "30d"

[jail.sshd]
enabled = true
log_path = "/var/log/auth.log"
date_format = "iso8601"          # 根据上一步结果修改：iso8601 或 syslog
filter = [
    'sshd\[\d+\]: Failed password for .* from <HOST>',
    'sshd\[\d+\]: Invalid user .* from <HOST>',
]
port = ["22"]
protocol = "tcp"
max_retry = 3
find_time = "10m"
ban_time = "1d"
backend = "nftables"             # Ubuntu 24.04+ 默认 nftables；旧系统可改 "iptables"
ignoreip = ["127.0.0.1/8", "::1/128"]
EOF
```

> ⚠️ `date_format` 必须与第 2 步判断结果一致，否则无法解析日志、不会触发封禁。

### 4. 启动并设置开机自启

```bash
# 创建运行时目录并持久化（防止重启后套接字目录丢失）
sudo mkdir -p /var/run/fail2ban-rs
echo "d /var/run/fail2ban-rs 0755 root root -" | sudo tee /etc/tmpfiles.d/fail2ban-rs.conf

# 启用并启动
sudo systemctl enable --now fail2ban-rs

# 查看服务状态
sudo systemctl status fail2ban-rs
```

### 5. 验证

```bash
# 服务运行状态
sudo fail2ban-rs status
# 期望输出：fail2ban-rs is running

# 查看启动日志，确认 sshd jail 已加载
sudo journalctl -u fail2ban-rs -n 20 --no-pager
# 期望看到：watcher started ... jail=sshd path=/var/log/auth.log
#           executor started ... backends="[sshd=nftables]"

# 查看当前封禁列表
sudo fail2ban-rs banned

# 查看 nftables 中是否生成了 fail2ban 规则
sudo nft list ruleset | grep -A10 fail2ban
```

**实测封禁**：从另一台机器用错误密码 SSH 登录 3 次以上，然后再次执行 `sudo fail2ban-rs banned` 和 `sudo nft list ruleset | grep -A10 fail2ban`，应出现测试 IP 和对应 drop/reject 规则。测试完解封：
```bash
sudo fail2ban-rs unban <测试IP>
```

### 6. 清理旧版 fail2ban（如之前装过）

```bash
sudo systemctl disable --now fail2ban 2>/dev/null || true
sudo rm -rf /etc/fail2ban /var/lib/fail2ban /var/log/fail2ban
```

## 🔄 阶段四：系统更新与漏洞修补

### 1. 开启自动安全更新
```bash
sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure --priority=low unattended-upgrades
# 在弹出的界面中选择 <Yes>，按回车
```

### 2. 执行一次全面更新与清理
```bash
# 刷新软件源并全量升级
sudo apt update
sudo apt upgrade -y

# 处理被系统保留（held back）的核心包（如 cloud-init）
sudo apt install --only-upgrade cloud-init
# 或者使用更激进的：sudo apt full-upgrade -y

# 清理无用依赖
sudo apt autoremove -y
```

### 3. 检查是否需要重启
```bash
[ -f /var/run/reboot-required ] && echo "需要重启" || echo "不需要重启"
# 若提示需要重启，执行 sudo reboot，稍后重连即可
```

## 📦 附：Docker 网络最佳实践提示
如果你后续使用 Docker，请勿使用默认的 `bridge` 网络。
*   **原则**：为不同的应用栈创建独立的自定义 bridge 网络，实现容器间的网络隔离。
*   **命令**：`docker network create my-app-net`
*   **启动容器时**：指定 `--network my-app-net`，同网络内容器可直接通过容器名 DNS 解析通信，不同网络默认隔离。
